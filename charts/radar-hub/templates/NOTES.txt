   hub Pod and must complete before the main container starts):
     kubectl -n {{ .Release.Namespace }} get pods -w
     kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "radar-hub.hubName" . }} -c migrate

2. Once both Deployments are Ready, open:
     {{ default "<hub.publicURL>" .Values.hub.publicURL }}

3. Sign in with the break-glass admin (or OIDC if configured) and verify:
   - The deployment-shape banner shows "self-hosted"
   - The Billing tab is hidden
   - The "Create organization" button is hidden

4. Connect a Kubernetes cluster with Radar CLI 1.8.3 or newer:
     kubectl radar cloud install \
       --hub-url {{ .Values.hub.publicURL | quote }} \
       --context YOUR_KUBECONFIG_CONTEXT

   The CLI confirms the kubeconfig target, preflights native Helm changes,
   and hands verified Argo CD/Flux installations back to GitOps. Browser
   approval requires an account allowed to add clusters to this organization.
   Guide: https://radarhq.io/docs/cloud/self-hosted/install#5-connect-your-first-cluster

5. Upgrade path:
     helm repo update
     helm upgrade {{ .Release.Name }} skyhook/radar-hub \
       --namespace {{ .Release.Namespace }}
   (the migrate initContainer re-runs on each rolling-update pod).

LICENSE STATUS
--------------
The license is optional at install. Without one the hub starts but the web UI
shows a license-required screen — set license.key (or license.existingSecret)
and redeploy to activate.

The hub logs license verification at boot. Look for:
  "license verified" — happy path
  "license is expired (warn-only ...)" — past exp; banner shown but writes still work
  "no license configured — hub is blocked ..." — set license.key + redeploy
  "license is invalid ..." — bad signature or claims; check the key you pasted
